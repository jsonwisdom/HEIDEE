1

The “No Means No” Static Code Check

AST analysis is the stronger version of this idea; PR #2 currently uses strict static allowlist checks.

This is the digital version of putting plastic covers on the electrical outlets. We walk through the code like a parent checking the house before bed:

“Is that a fetch? Is that a WebSocket? Is that some sneaky window["fetch"] trying to look innocent?”

If a capability is not on the approved fridge list, the validator responds with pure parental energy:

“Absolutely not. Try again.”

No “but all the other apps are doing it.” No “it’s probably fine.” Unknown capability means validation failure.

2

The “I Can See Everything You’re Doing” Information-Flow Check

This is the parent who somehow knows you ate the last cookie even though you were very quiet about it.

  • This is family stuff.
  • This is allowed to leave the house.
  • This is never allowed to leave the house.

The formal goal is to prove private family data cannot quietly sneak out a back door. Roadmap layer: PR #2 does not currently claim exhaustive information-flow proof.

3

Model Checking = The Family Meeting That Never Ends

You sit the entire program down at the kitchen table and ask: What happens if someone says NO to the Joy Gate? What if a new file appears without approval? What if the Easy Button gets pressed when it should not?

The checker walks through modeled scenarios until the modeled rules hold. Roadmap layer: PR #2 does not currently claim exhaustive model checking.

4

Theorem Proving = The Nuclear Option

Also known as: Grandma’s Rules.

This is where rules are precise enough for a computer to mathematically prove certain bad states cannot happen under the model.

Roadmap layer: PR #2 does not currently claim a machine-checked theorem proof.

5

Policy-as-Code = The Family Constitution on the Fridge

DEFAULT = DENY

ONLY these runtime reads are approved:
- ./metadata.json
- ./fixtures/instrument.blank.json

NO network surprises.
NEW runtime resources require explicit approval.

Every run checks the fridge first. Beautifully recursive. Beautifully parental.

NEW RUNTIME RESOURCE
= EXPLICIT METADATA DECLARATION REQUIRED

Current enforcement target: allowlist-first static validation of runtime reads and common network/resource escape paths. This is a strong static boundary, not a claim that arbitrary future bundled JavaScript has been mathematically proven safe.

What is actually checked today?

Receipts before bragging.

Current PR #2: metadata invariants, JOY-gate behavior, receipt-field parity, JavaScript syntax, declared runtime-read allowlisting, and static rejection of common network/resource escape paths.

Not claimed yet: exhaustive information-flow proof, exhaustive model checking, or theorem-prover certification.

Green CI means the declared validator passed. It does not magically mean “all software safety has been proven forever.”

What parents should remember

Safety does not mean “trust the app.”

It means the app can show what it is allowed to do, fail when something unknown appears, and keep family decisions with the family.

JSON enables the capability. JOY & Family choose the meaning.
